## One-line description

AVAX Impact is an open builder-attribution standard, indexer, and dashboard that measures which apps generate users, transactions, fees, and asset flows across Avalanche C-Chain and Avalanche L1s.

## Short description, approximately 75 words

AVAX Impact gives Avalanche applications a standard way to identify the transactions they generate. Apps append a small builder code to supported EVM transactions. An open indexer validates the code and publishes application-level metrics through an API and dashboard. The MVP will support C-Chain and one Avalanche L1, ship SDKs for common TypeScript wallet stacks, and onboard three pilot apps. This gives builders and ecosystem programs auditable data for discovery, grants, incentives, and economic research.

## Project summary

Avalanche can identify the protocol or contract used in a transaction, but it usually cannot identify which frontend, wallet, bot, or backend automation generated that transaction. The same protocol can be accessed through many applications, and the same application can generate activity across C-Chain and multiple Avalanche L1s. Today, that application-level contribution is difficult to measure.

AVAX Impact closes this attribution gap. Participating applications register a human-readable builder code and append a compact attribution suffix to transactions they initiate. The suffix follows an EVM-compatible format based on ERC-8021. A public indexer decodes the suffix, validates it against the registry, and exposes application-level metrics through an open API and dashboard.

The MVP will include a registry contract, TypeScript SDK, decoder, indexer, REST API, public dashboard, documentation, and three pilot integrations. It will initially support Avalanche Fuji, C-Chain, and one production Avalanche L1. The project will be open source and will not issue a token.

## Problem

Avalanche's public data answers which address called which contract, but not reliably which application facilitated the action. This creates five problems:

1. Builders cannot prove the activity their products generate when users interact with shared protocols.
2. Team1 and other ecosystem programs must rely heavily on self-reported metrics when evaluating project impact.
3. Users have no neutral application-level discovery leaderboard.
4. Economic activity is fragmented across C-Chain and independent Avalanche L1s.
5. Avalanche's emerging GCP and GCI research lacks a standardized application-attribution input.

Protocol analytics alone do not solve this. A DEX contract can show total volume, but it cannot distinguish activity generated by its own interface, an aggregator, a wallet, a trading bot, or another application.

## Solution

AVAX Impact consists of four layers:

1. **Attribution standard.** A compact data suffix identifies one or more registered builder codes without changing normal contract execution for compatible calls.
2. **Builder registry.** An onchain registry maps codes to owners, payout addresses, and metadata URIs.
3. **Indexer and API.** A chain-aware indexer parses supported transactions on C-Chain and Avalanche L1s and calculates builder-level metrics.
4. **Public dashboard.** Builders and ecosystem teams can inspect transactions, users, fees, contracts, and asset flows attributable to each app.

The design is compatible with existing EVM tooling and does not require a new L1, token, bridge, wallet, or custody layer.

## Why Avalanche

Avalanche is unusually well suited to this project for three reasons.

First, Avalanche is becoming a network of sovereign L1s. Each L1 can use its own fee model, native token, validator rules, and application stack. This creates a stronger need for a shared attribution layer than on a single-chain ecosystem.

Second, Avalanche Foundation's 2026 economic research agenda prioritizes measuring ecosystem output, understanding value capture, and connecting activity to long-term network sustainability. Application attribution is a missing input for that work.

Third, Avalanche already has strong institutional, payments, RWA, gaming, and consumer applications. AVAX Impact helps those projects prove their contribution without asking them to migrate contracts or adopt a new execution environment.

## Why now

Base launched Builder Codes and ERC-8021 in April 2026, demonstrating that application-level transaction attribution is both technically practical and useful for ecosystem incentives. Avalanche does not yet have a visible equivalent in the official Team1 ecosystem catalog.

At the same time, Avalanche Foundation published its economic research agenda in July 2026 and the Gross Chain Income framework in August 2026. The ecosystem is explicitly asking how to measure value before designing capture and distribution mechanisms. AVAX Impact can provide the application-level data needed for that next step.

## Innovation and differentiation

AVAX Impact is not a generic analytics dashboard and not a direct Base clone.

Its Avalanche-specific scope includes:

- one builder identity across C-Chain and independent Avalanche L1s;
- chain-aware fee and gas-token normalization;
- application-level metrics across sovereign networks;
- support for Avalanche-native ecosystem research and grant reporting;
- a future path to ICM-based registry synchronization;
- an open integration layer that wallets, apps, indexers, and L1 operators can adopt.

Existing Avalanche explorers and analytics products primarily measure chains, contracts, tokens, or protocols. AVAX Impact measures the offchain applications that generate the transactions.

## Technical approach

The attribution suffix will be compatible with ERC-8021 where contract behavior permits extra calldata. The SDK will apply attribution only through explicit opt-in and will include compatibility checks for contracts that validate calldata length or use custom fallback logic.

The registry will contain no user funds and will not sit in the execution path of attributed transactions. If attribution is missing, malformed, or unsupported, the original application transaction must remain unaffected. The indexer treats attribution as metadata, not authorization.

The initial indexer will use Node.js or Go workers, PostgreSQL, and Avalanche RPC/Data API sources. The dashboard will use Next.js. Smart contracts will be implemented and tested with Solidity and Foundry.

## Risks and mitigations

**Contract compatibility.** Some contracts reject extra calldata. The SDK will use explicit opt-in, maintain a compatibility corpus, and never claim universal support.

**False or copied attribution.** The registry proves code ownership, but any sender could copy a public suffix. The MVP will distinguish declared attribution from higher-assurance attribution and document trust assumptions. Later versions can add signed execution policies or wallet attestations.

**Low adoption.** Three pilot integrations are a grant milestone, not a post-grant aspiration. The MVP will prioritize simple integrations and public examples.

**Misleading metrics.** The dashboard will publish methodology, separate raw facts from derived estimates, and avoid presenting volume as equivalent to economic value.

**Single-maintainer risk.** Automated tests, reproducible deployments, public documentation, and an open license reduce dependency on the applicant.

## Ecosystem benefit

AVAX Impact is a public-good layer that benefits builders, users, L1 operators, Team1, analytics providers, and the Avalanche Foundation. It makes successful apps easier to discover, gives new builders a measurable growth path, and provides auditable evidence for ecosystem support decisions.

The project does not compete with Avalanche protocols for liquidity or users. It makes the contribution of existing applications visible.
